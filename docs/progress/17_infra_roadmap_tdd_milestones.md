# 17. AgentBrowser 인프라 고도화 로드맵 (TDD 마일스톤 + 작업그래프 + 검사노드)

## §1. 목표 및 설계 원칙
사용자 제시 7개 아이디어를 **하나의 로드맵**으로 통합. 핵심 방향:
- 봇탐지 회피 강화 (인간행동·신뢰지문)
- 자원 격리 (컨테이너·포커스 분리)
- 지속 수집 (RAG형 상주 에이전트)

적용 원칙 (프로젝트 확정 기준):
- **TDD**: 모든 마일스톤은 실패 테스트 → 구현 → 통과 순서
- **ruff 클린 100%**, pydantic v2, OOP 표준
- **검사노드(Quality Gate)**: 각 마일스톤 종료 전 자동/수동 검증 지점
- **작업그래프**: 마일스톤 간 선후행 의존성 명시 (병렬 가능 노드 vs 직렬 필수 노드)

## §2. 작업 그래프 (마일스톤 의존성)

```
[M0: 기반 조사] ──┬─> [M1: on-demand 생존확인(#4)]
                    ├─> [M2: 링크위치 마우스이동(#5)]
                    ├─> [M3: DDG/Google 인덱스 비교+쿼터(#2,#3)]
                    └─> [M4: 구글제약해제적용(#1)]
                              │
              (M1+M2 선행) ──┴─> [M5: 포커스분리+컨테이너(#6,#7 전단)]
                                      │
                            (M5 선행) ──> [M6: 도커 RAG 상주에이전트(#7)]
                                              │
                                    (전체) ──> [M7: 통합 E2E 검증]
```

- **병렬 가능**: M1, M2, M3, M4 (서로 독립)
- **직렬 필수**: M5는 M1+M2 결과 활용, M6은 M5 격리 토대 위, M7은 전체 통합

## §2-1. AgentForge 롤 주입 + 팀 위임 원칙 (필수)
모든 마일스톤 위임 시 **AgentForge 롤 시스템 주입은 필수** (검증용 한정 아님, 모든 위임에).
위임 구조는 작업 성격에 따라 단일/복수를 분리:

| 마일스톤 | 위임 형태 | AgentForge 롤 | 팀 구성 |
|---|---|---|---|
| M0 조사 | 단일 에이전트 | analyst(R01) | 1명 (검색/수집 독점 원칙) |
| M1 구현 | 단일 작업자 | executor(R07) | 1명 |
| M2 구현 | 단일 작업자 | executor(R07) | 1명 |
| M3 조사+분석 | 조사 단일 + 분석 복수 | analyst(R01) ×A/B + critic/validator | 1(수집)+복수(검토) |
| M4 구현 | 단일 작업자 | executor(R07) | 1명 |
| M5 구현+검증 | 구현 단일 + 격리검증 복수 | executor(R07)+validator(R09) | 1+복수 |
| M6 컨테이너 | 구현 단일 + 지문검증 복수 | executor(R07)+validator(R09) | 1+복수 |
| M7 통합 | 복수 검증팀 | validator(R09) ×다수 | 복수 |

**핵심**:
- 검색/수집(M0, M3수집)은 **단일 에이전트 독점** (복수 위임 금지 — 사용자 원칙).
- 선정/분석/검토/설계검증은 **복수 에이전트 팀** (신뢰도·품질 향상).
- 모든 위임 컨텍스트에 AgentForge SYSTEM_PROMPT + soul_context 주입 (skip_context_files 우회).
- Botler는 직접 도구 호출 금지 — 오직 delegate_task 로만 위임.

### M4. 구글 사용 스위치 내장 (#1)
- **설계 방침**: 구글 검색은 **스위치(플래그)로만 내장**, 기본값 OFF (구글 제외 원칙 유지).
  - `SearchConfig.enable_google: bool = False` (pydantic 필드, 기본 비활성)
  - CLI/설정에서 `--enable-google` 명시 시에만 GoogleSearch 클래스 활성화
  - GoogleSearch 셀렉터/로직은 코드에 구현하되 **기본 경로로는 호출되지 않음**
- **TDD 순서**:
  1. RED: enable_google=False 일 때 engine="google" 호출이 거부(또는 fallback)되는 검증
  2. GREEN: 스위치 ON 시에만 GoogleSearch 동작하도록 분기 구현
  3. **테스트에서는 구글 제외**: 모든 단위/통합 테스트는 enable_google=False 고정.
     구글 실제 검색 검증은 TDD 테스트 범위 밖(온디맨드 수동 검증만, M0/M3서 이미 1회 확인됨).
- 검사노드(Q4): ①단위(스위치 OFF 거부/ON 분기) ②ruff ③**구글경로는 테스트에서 제외됨 증명**(테스트 스위트에 google 활성 케이스 0건)

### M5. 포커스 분리 + 컨테이너 기반 + 원격디버깅 플래그 개선 (#6,#7 전단)
- **추가 범위 (사용자 지시, 2026-08-16)**: 현재 `--remote-debugging-port` + `--load-extension` 조합이
  Mac 에서 "원격 디버깅 허용" 프롬프트 + "자동화 도구" 배너를 유발 (봇탐지 회피 관점 모순).
  → **원격디버깅 플래그를 포트 개방 방식에서 파이프 방식으로 변경**하여 OS 레벨 알림 제거.
- **TDD 순서**:
  1. RED: `build_launch_command` 가 `--remote-debugging-port` 를 포함하거나,
     `cdp_bridge.connect` 가 포트 URL(`http://127.0.0.1:port`)로 붙는 현재 방식 실패케이스
  2. GREEN:
     - `launcher.py`: `--remote-debugging-port={port}` → `--remote-debugging-pipe` 로 변경
       (포트 미개방 → "리모트 디버깅 허용" 프롬프트 미발생)
     - `cdp_bridge.py`: `connect_over_cdp("http://...")` → pipe 기반 연결(`connect_over_cdp` pipe 모드
       또는 Playwright pipe attach) 로 변경. `navigator.webdriver===false` 검증 로직 유지.
     - `--load-extension` 은 유지하되, 배너 노출 최소화를 위해 조건부 로드 검토
  3. 실제 검증: Chrome 기동 시 포트 9222 미개방 확인 (`lsof -i:9222` null),
     에이전트 브라우징 중 "자동화 도구" 배너/알림 미발생, webdriver=False 유지
- 검사노드(Q5): ①격리 단위 ②ruff ③사용자 워크플로우 방해없음 실측
  **④포트 미개방+알림없음 실측** (신규)

### M6. 도커 컨테이너 + GPU지문 주입 (#7, M5 토대)
- **범위 확정**: 컨테이너 구성 + 호스트 GPU/디스플레이 지문 주입은 **실제 구현**.
  단, **지속 수집/RAG 축적 로직은 설계 문서로만 한정** (사용자 지시: 지속수집은 설계까지만).
  → 즉 M6은 "컨테이너에서 에이전트 브라우저가 호스트 지문으로 구동되는 것"까지 실제 완료,
    그 안의 "상주 에이전트가 주제를 지속 검색해 RAG로 쌓는" 부분은 별도 설계서(17-RAG안)로만 작성.
- **TDD 순서**:
  1. RED: 컨테이너 내 Chrome 이 호스트 GPU/디스플레이 지문을 갖지 않음 실패
     (navigator.gpu / hardwareConcurrency / WebGL renderer 불일치)
  2. GREEN: docker-compose `--gpus` + env 주입 + `--use-gl` 로 호스트 지문 반영
     (컨테이너별 미세 차이 부여해 동일지문 탐지 회피)
  3. 실제 검증: 컨테이너 기동 → 내부 Chrome 이 navigator.webdriver=False + 지문 일치 확인
- 검사노드(Q6): ①지문일치 단위 ②ruff ③컨테이너 격리+지문주입 E2E
  (RAG 지속수집은 제외 — 설계 문서 17-RAG안.md 로 한정)

> **17-RAG안.md (설계한정)**: 컨테이너 상주 에이전트의 지속적 주제검색 → memory/(FTS5) 적재 → 질의 시 RAG 컨텍스트 제공 구조. 실제 구현 제외.
