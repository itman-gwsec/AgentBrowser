# Rate Limit(429) 대응 프로토콜 및 모델 선정 정책 (2026-08-13)

## 결정
AgentBrowser 위임 작업 중 429(Rate Limit) 발생 시 표준 대응 프로토콜을 확정한다.
1. **즉시 10분 대기** — 재시도 금지, 쿨다운 확보.
2. **리밋 해제 확인** — 10분 경과 후 단일 probe 호출로 해제 여부 검증.
3. **상황 분석** — 디스크 실측(`docs/`, `README.md`)으로 완료 지점 파악, 중복 수행 방지.
4. **이어서 진행** — 미완료 잔여 작업만 재개.

유료 모델(qwen3.8 고민 중) 선정은 nous project 프롬프트 캐싱/요금 문의 답변 후 결정한다. 유료 모델도 rate limit이 존재하므로 **무한 병렬 확장 금지** → 동시 위임 **2개 상한**을 유지한다.

## 근거(사실)
- [사실] 현재 모델 `tencent/hy3:free`(무료) 사용 중, 다수 위임 시 429 반복 발생 실측. `~/.hermes/config.yaml` delegation.reference_models에 `hy3:free` + `ling-3.0-flash:free` 등록(L136).
- [사실] `README.md`(19.6KB)·`docs/reports/03_final_report.md`(26.4KB)는 429 속에서도 디스크에 정상 생성됨(자기보고 timeout과 무관, 파일 실재 확인).
- [사실] 사용자: 유료 모델 qwen3.8 고민, nous project에 프롬프트 캐싱/요금 문의 진행 중.
- [반대증거] 유료 모델도 rate limit 존재 → 병렬 무한 확장 불가. 동시 2개가 안정 상한.

## 적용
- 429 발생 시 10분 대기 프로토콜 즉시 적용.
- 잔여 작업(`docs/04_user_manual.md` 사용메뉴얼)은 리밋 해제 후 이어서 수행.
- 동시 위임 2개 상한 준수(유료 전환 후에도 유지).

## 버전/이력
- 2026-08-13: v1. 사용자 지시("429발생하면 10분 단위로 리밋 해제 대기와 확인 후 상황분석하여 이어가는 것으로 하자. 유료 모델은 qwen3.8로 고민 중. nous project쪽으로 프롬프트 캐슁등의 요금에 대해서 문의해놓은 상태. 답변에 따라서 모델을 선정. 유료 모델 역시도 rate limit 존재. 무한대로 병렬 확장 불가") 직접 인용.
